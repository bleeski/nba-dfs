# S2. What the repo review changed in the sketch, and why

**Date:** 2026-10-13. **Inputs:** S1 (first-principles sketch, written before opening any prior repo) and the four repo-review memos: RR1 (mlb-dfs), RR2 (nfl-dfs), RR3 (nhl-dfs, golf-dfs, soccer-dfs), RR4 (dfs-os, nba-betting-system, bleeski/NBA, dfs-architect). The full revised design is `docs/ARCHITECTURE.md`; this file records only the changes and the evidence behind each.

## The one finding that reshapes the plan

No prior engine showed an edge, and most of the money lost was lost at lock time.

- MLB: Classic finished at the 49.8th percentile (random) and Showdown worse than random; 67 entries locked blank in later slates nobody built (RR1, VERIFIED in its results ledger and changelog).
- NFL: 348 entries, minus $92 on $223, finishing percentile indistinguishable from random; the model that actually ran was "maximize projected points"; one night 12 of 13 entries locked blank (RR2, VERIFIED).
- NHL: Classic cashed 23 of 136 against 32.2 expected at random; DraftKings refused 8 of 28 late rows (RR3, VERIFIED). Golf: 7 entries locked blank after environment repair inside the entry window.
- dfs-os, dfs-architect, bleeski/NBA, nba-betting-system: none ever ran a real nightly cycle (RR4, VERIFIED).
- Process grew faster than results in every repo: MLB about 100,000 lines with about 80% of pull requests on records, governance or plumbing; NHL 106 open decisions queued for the user and an 18 to 35 minute test suite (RR1, RR3).

**What it means for the design:** delivery is the first goal-1 and goal-2 lever, the model's sophistication must be earned by measurement, and the build process itself needs written limits.

## Changes

| # | Change | Why (evidence) | Effect on the two goals |
|---|---|---|---|
| 1 | **Phase 1 becomes a thin end-to-end skeleton run on real preseason files before Oct 20**, including the user's upload and DraftKings' "uploaded N of N" read-back. Sophistication (QA loop, calibrated field, conditioned late swap) moves to later phases and must beat the simpler version on scorecards to stay. | Every prior project that specified before running never ran (RR4); MLB and NFL built large machinery with no measured edge (RR1, RR2). | An entry that locks blank has zero chance at both goals. |
| 2 | **Only DraftKings validity blocks delivery.** Every other check (strategy, data freshness, concentration, QA) labels the output in the brief and never stops a file. | A weather check that changed no number blocked two NFL slates (RR2); a convention enforced as a rule helped cause a 37-entry MLB night with no file (RR1); never-passing gates were bypassed in golf, soccer, and NHL (RR3). | Removes the most common self-inflicted washout. |
| 3 | **Night plan by slate in lock order.** Each slate gets a validated baseline file before any slate is improved. The brief shows unfilled entries next to P(washout). | 67 MLB entries locked blank in later slates nobody built (RR1). | Washout has a delivery cause the math does not model; this makes it visible and fixes it first. |
| 4 | **Completeness check after every upload.** The user re-downloads the entries file; the engine confirms every entry has a full lineup and matches what was exported, and records which file was uploaded. | NFL 12 of 13 entries locked blank after a file was built (RR2); for 395 of 480 MLB entry IDs nobody can tell which file was uploaded (RR1). | Catches silent upload failures before lock. |
| 5 | **Versioned upload file names** (`<slate>_<lock time>_v<n>.csv`) and a per-cell "locks soon" warning. | NHL versions were all named `DKEntries.csv` and the late one was refused after first tip (RR3). | Prevents uploading the wrong version near lock. |
| 6 | **One parser, one clock, one identity rule, one team-code map.** Lock times come from each file's Game Info on every run, never typed by hand. Identity is keyed by person plus role (CPT or UTIL) per slate, because DraftKings IDs change between slates. Reviewed name matches persist across nights. | Drifted copies of one rule were MLB's most common root cause; a stale lock list got 7 of 16 late-swap rows rejected; a doubleheader skewed the lock clock by 65 minutes (RR1). Soccer IDs: 0 of 26 shared across two slates (RR3). NFL name mismatches blocked 5+ slates (RR2). | Removes a whole family of invalid or stale files. |
| 7 | **Encoding rules.** Salary files are UTF-8 with a byte-order mark; entries files have no byte-order mark and are cp1252 when names carry accents. The parser detects and the exporter mirrors the source encoding. | Byte scan of the user's Downloads (RR3). | Prevents mangled names and rejected rows. |
| 8 | **Contest facts table built from the user's DraftKings entry-history export**, keyed by contest family (name pattern, fee, size). Payout pastes become optional extras, not a dependency. | Payout tables "never arrived by optional paste" all MLB season (RR1); golf's default curve paid 35.6% to first against a real 10 to 18%; NHL assumed 5,000-entry fields that were about 400 (RR3); the export carries field size, places paid, and prize pool (R8, RR1, RR2, RR3). | Better thresholds for both goals at near-zero user effort. |
| 9 | **A fresh DKSalaries export is required for the final pre-lock build.** It is the only DraftKings source of `Status` and `Starting`, and DraftKings adds players after earlier downloads. | MLB's best late-news source was this export (RR1); NHL and golf saw players added late (RR3). | Gives confirmed starters with no terms problem (manual download). |
| 10 | **Determinism rules.** No wall-clock time limits in solvers (problems are small; use deterministic limits only); every random draw keyed by stable identifiers (scenario index, game ID, person ID), never by row order. | NHL's time-limited solver changed lineups on a busy laptop; golf drew noise by row position (RR3). | Common random numbers and replay depend on it. |
| 11 | **News must reach the field, and a test proves it.** A synthetic scratch must raise the simulated field's ownership of the beneficiary; the morning scorecard tracks news-driven chalk misses separately. | NHL built ownership from a simulated field and still missed news-driven chalk by about 10x (50.7% actual, 4.7% predicted) because news never reached the field model (RR3). | Ownership errors on late chalk corrupt both thresholds and duplicate estimates. |
| 12 | **Strategy terms are graded against standings before they carry weight.** Leverage and duplication effects start at what the field model implies and are checked against real fields weekly; field knobs are fitted with heavy shrinkage. | MLB leaned contrarian and favored 4-man stacks while winners were chalkier and favored 5-man stacks (RR1); NFL construction features flipped sign game to game (RR2); unique Showdown lineups were the worst feature (RR2). | Avoids paying for differentiation the field does not reward. |
| 13 | **Concentration guardrails live in code**: a cap on the share of the night's entries using any one player (default 60%) and a reported share per game across formats. | Across 8,007 field portfolios, 85%+ of entries on one player raised the zero-paid rate 1.4x to 12x; the NFL engine shipped 94% on one player and cashed 0 of 18 (RR2). | Direct washout protection. |
| 14 | **Separate selection and reporting scenarios.** The portfolio is chosen on one scenario set and its reported probabilities come from a fresh set. | MLB required it after selection bias flattered reports (RR1). | Honest numbers in the brief. |
| 15 | **Big-field first-place odds use a fitted upper tail.** Top 1% is read from the sampled field; P(first) in large fields fits the field's upper tail and applies the binomial step. Both P(first) and P(top 0.1%) are reported beside Goal 1. | NFL's old path overpriced first place by 18x to 280x from a sampled field (RR2); the user's NFL instruction was to "err on side of trying to win large prizes" (RR2). | Correct secondary metrics for the user's prize preference. |
| 16 | **Late-swap safeguards.** Edit DraftKings' current export in place; never regenerate from the blank template; never move a locked player; rehearse once on a real post-lock file before Oct 20; settle whether DraftKings accepts uploads that still carry `(LOCKED)` cells and whether entries in later games can be filled after the first lock, with a $0.25 test. | Regenerating from the template moved locked players in 107 cells (RR2); NHL late swap broke on its first real post-lock file (RR3); MLB saw post-lock fills apparently accepted but could not confirm (RR1). | Late swap is where late news pays; it must not void entries. |
| 17 | **Showdown lineups carry a scenario label** (the game script in which each lineup wins most often, for example "home blowout" or "close game, overtime"), computed from the scenarios it covers. | The user asked for named game theses per Showdown lineup in NFL (RR2). | Makes the portfolio's coverage of ways the night unfolds visible, which is the user's hunch in plain view. |
| 18 | **The researcher covers players the engine does not yet rate and can describe a player with no history.** User overrides are scored as their own layer. | NFL candidate pools silently left out good players and priced last season's roles (RR2); RR3 recommends scoring user overrides. | New roles early in the season are where edges appear. |
| 19 | **Data freshness labels.** The brief lists every input as real, cached, fallback, or missing, with its timestamp. Stale injury report, unmatched players, or no starters near tip raise an alert (label only, per change 2). | Most past errors in the user's betting project "came from stale schedules, missing injuries, or incomplete data"; dfs-os wrote upload files with 0 of 175 starters confirmed (RR4). | Prevents confident lineups built on stale inputs. |
| 20 | **Ownership is stored in one unit with nightly sum checks** (800% Classic; 100% Captain plus 500% UTIL Showdown). DraftKings' AvgPointsPerGame is never used as a projection (it is 0.0 for players with no history). | dfs-os mixed units; AvgPointsPerGame zeros (RR4). | Prevents silent field-model errors. |
| 21 | **Process limits are part of the design:** smoke test under 60 seconds, full test suite under 5 minutes, at most 5 open decisions queued for the user, no engine code edits from 60 minutes before first lock to last lock (a hook blocks edits to `src/` during a night run), QA time-boxed at 10 minutes per iteration. | NHL's 21 to 24 minute pre-build check, 18 to 35 minute test suite, and 106 open decisions; MLB QA ran 11 to 33 minutes; golf repaired its environment inside the entry window (RR1, RR3). | Keeps the user's nightly time and attention on the slate. |
| 22 | **Privacy:** run data, standings (which contain other users' names), and entries are never committed; the GitHub repo is private. | NHL pushed entered lineups to a public repo before lock (RR3); standings files contain other users' names (RR2). | Protects the user's edge and other players' privacy. |

## Reuse decisions (details in ADR-018)

- **Port, with tests: the entry-history export parser rules** (NHL `learn/entry_history.py` plus `results.py`; NFL and MLB built the same thing independently). Three independent implementations of the same 14-column export is the strongest reuse signal in the review. It is small (standard library and numpy) and reads a file whose format is shared across sports.
- **Port: NHL `normalize_name`** (accent folding and suffix handling), with NBA test cases.
- **Learn from, do not copy:** NFL `dk.py` file-layout rules, MLB `day_plan.py` (lock-order planning), MLB standings-pull rules, golf's 11-check blocking list, NHL's skill setup (engine runs before the model reads; write denial).
- **Do not reuse:** any optimizer, allocator, selector, field sampler (MLB's had a Showdown duplicate bug), pipeline, claims or gate registry, or anything that calls DraftKings endpoints.

## What the repo review did not change

- The goals math (Part A of S1), the shared night simulation, the LLM/solver boundary, and the manual DraftKings I/O all stand. NFL's experience (a 23-way tie for first paying each entry 5.4% of the advertised prize) strengthens the prize-share treatment of duplicates.
- dfs-os's own PRD named "Monte Carlo simulation plus a simulated field" as the theoretically correct approach and deferred it (RR4). The design keeps it, but behind change 1: it must run end to end in its simplest form first.
